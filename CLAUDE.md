# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity 6 (6000.3.6f1) first-person gothic action game. The design doc is `gameplan.md` (the game is titled "The Crimson Museum" there; the project folder is "Crimson Nights"). **Phases 1 (Prototype) and 2 (Combat Prototype) are done**: the cube-enemy arena has dodge, perfect dodge, weapon switching, enemy attacks and stagger, a punch combo and a style meter. Next is **Phase 3 — Museum Prototype** (a small gothic section of the mansion with lighting, doors, keys, exhibits and environmental storytelling), aiming at the first milestone: *walk into the Grand Gallery, fight a vampire, dodge its attack, shoot it, kill it, keep exploring.* The design doc prefers simple, modular systems (ScriptableObjects for weapons/enemies, NavMesh for enemies) over complex architecture, and keeps scope deliberately small. Check proposed features against its vertical-slice and scope rules.

Git repository (branch `main`, remote `origin` = github.com/ChrisOspina/Crimson-Nights). `.gitignore` excludes Unity's generated folders (`Library/`, `Temp/`, `Logs/`, `UserSettings/`, IDE files). `.gitattributes` routes audio, textures, models, fonts, video and PDFs through **Git LFS**, so new binary types need an LFS rule added there before they're committed. Always commit `.meta` files alongside their assets. No assembly definitions and no tests yet, so all scripts compile into `Assembly-CSharp`.

## Building / running

There's no CLI build pipeline. Work happens in the Unity Editor (installed at `C:/Program Files/Unity/Hub/Editor/6000.3.6f1/Editor/Unity.exe`). The only scene in Build Settings is `Assets/Scenes/SampleScene.unity`, which holds the combat test arena. The arena, player combat setup, data assets and enemy prefab are generated by **Tools ▸ Crimson Nights ▸ Build Prototype Arena** (`Assets/Scripts/Editor/PrototypeArenaBuilder.cs`). Re-running it rebuilds the `PrototypeArena` root and player instance, but reuses existing data assets, materials and the enemy prefab, so delete one of those to regenerate it. When the scene layout changes, update the builder rather than making scene-only edits that a re-run would wipe. Compile errors show up only in the Editor Console (or `Logs/` / `%LOCALAPPDATA%/Unity/Editor/Editor.log`), so changes can't be verified without Unity. Say so when reporting work.

Test Framework 1.6 is installed. If tests get added, run them headless with:
`Unity.exe -batchmode -projectPath . -runTests -testPlatform EditMode -testResults results.xml` (add `-testFilter <name>` for a single test). This needs an asmdef referencing the test assemblies, and the Editor must not already have the project open.

## Architecture

A diagram of the player setup, with planned systems, is at `docs/architecture.drawio`. Update it when you add or rewire systems.

The player is built on **Unity Starter Assets – First Person** (`Assets/StarterAssets/`):

- `PlayerCapsule.prefab` (Player tag, layer 8 `Player`) contains `CharacterController`, `FirstPersonController`, `StarterAssetsInputs`, `PlayerInput`, `BasicRigidBodyPush`, plus the project's `PlayerMovementAudio`, `Health`, `PlayerDeath`, two `Firearm`s (revolver, shotgun), `WeaponSwitcher`, `MeleeWeapon`, `PlayerDodge`, `StyleMeter` and `PlayerHUD`. Viewmodels sit under `PlayerCameraRoot`: the revolver and shotgun use the M1911 and Bennelli_M4 models from `Assets/Low Poly Weapons VOL.1/` (a Built-in RP pack whose shared `Gun_MAT` was converted to URP/Lit by hand). The arena builder copies each model in (`SetupGunModel`), turns it 180° because the pack's guns face -Z, scales it to a set length from its mesh bounds and puts the `Muzzle` on its front face (each gun also has an `EjectPort` child, which the builder keeps when it swaps the model). If a model is missing, it falls back to placeholder cubes, and the fist is still a cube. There is no sword: melee is punches only.
- Input flow: `PlayerInput` (Send Messages, using `StarterAssets/InputSystem/StarterAssets.inputactions`) → `StarterAssetsInputs.On<Action>` store plain fields (`move`, `look`, `sprint`, `fire`, `melee`, `reload`, `dodge`, `switchWeapon`) → components read those fields each frame. Button actions only send on press, so `fire`/`reload`/`dodge`/`switchWeapon` are latched flags that the consuming component clears; `melee` (like `sprint`) is a PassThrough action so it also gets the release, which hold-for-heavy needs. The game has **no jumping**: the Jump action, input field and controller jump logic have all been removed, so don't reintroduce them. Current bindings: LMB/RT fire, Space/RB melee, R/West reload, RMB/South dodge, Q/scroll/North switch weapon. New actions (crouch, etc.) should follow the same pattern: add the action to `StarterAssets.inputactions`, add an `On<Action>` handler and field in `StarterAssetsInputs`, then consume the field. Note that `Assets/InputSystem_Actions.inputactions` is the separate project-wide actions asset and isn't what the player uses.
- `FirstPersonController.Update` runs `ApplyGravity → GroundedCheck → Move`, and the camera pitch in `LateUpdate` drives `PlayerCameraRoot` (followed by the scene's `PlayerFollowCamera`, a CM3 `CinemachineCamera` with HardLockToTarget + RotateWithFollowTarget). Don't use the Starter Assets `PlayerFollowCamera.prefab`/`MainCamera.prefab`: they're legacy Cinemachine 2 components. `Grounded` comes from a sphere check against `GroundLayers`, not `CharacterController.isGrounded`. The player only leaves the ground by walking off ledges.
- **The Starter Assets scripts have been modified locally.** Jumping was stripped from `FirstPersonController`, `StarterAssetsInputs` and the mobile `UICanvasControllerInput`; `StarterAssetsInputs` has the combat inputs, and `StarterAssets.inputactions` has Fire/Melee/Reload/Dodge/SwitchWeapon, and `FirstPersonController` has a `MovementLocked` flag (input movement off, gravity and look still on) that `PlayerDodge` sets during a dash. Re-importing the Starter Assets package would overwrite these edits. Prefer adding behaviour in separate components that hook into the controller (events, or reading state in `LateUpdate`) rather than growing the controller itself.

Project-owned code lives in `Assets/Scripts/`:

- **Combat/**: `Health` (shared by the player and enemies; events `Damaged(DamageInfo)`, `Died`; `Invulnerable` ignores damage), the `DamageInfo` struct, and `SlowMotion`, the only code allowed to change `Time.timeScale` (it times itself on unscaled time and survives scene reloads). Anything that deals damage finds the target with `GetComponentInParent<Health>()` on the hit collider.
- **Weapons/**: `Firearm` (hitscan from `Camera.main`; `FirearmData.PelletCount`/`SpreadAngle` make the shotgun, and pellets hitting the same target add up into one `DamageInfo`), `WeaponSwitcher` (cycles the firearms; only the equipped one is enabled and its viewmodel visible, holstering cancels a reload) and `MeleeWeapon` (off-hand punches, always on its own button, not switched; OverlapSphere in front of the camera). Taps chain through `MeleeData.LightCombo` (Jab → Cross → Hook finisher) while each punch starts within `ComboWindow` of the last one's cooldown, and presses during a punch are buffered for `InputBufferTime`. Holding past `HeavyHoldTime` throws a Haymaker, which resets the chain. Finishers and the heavy use `HeavyHitClip`. Both `Firearm` and `MeleeWeapon` raise `Hit(AttackHit)` after damaging a target (attack name, weapon, finisher flag, whether it killed), which is how the style meter scores them. The player has one `Firearm` component per weapon, told apart by `Data`. Tuning lives in ScriptableObjects `FirearmData` (`Revolver.asset`, `RelicShotgun.asset`) / `MeleeData` (`Fists.asset`) under `Assets/Data/Weapons/`. `Firearm`/`FirearmData` were renamed from `Revolver`/`RevolverData` (same script GUIDs). Each shot throws a `FirearmData.CasingPrefab` (a Rigidbody with `Casing`, which shrinks away after a few seconds; on the Player layer, with collision against the player's CharacterController turned off) out of the firearm's `EjectPort`, and `FirearmData.RoundIcon` is the sprite `PlayerHUD` draws once per round in the magazine (with no icon it falls back to "6 / 24" text). The arena builder makes both from the DuNguyn Bullets Pack (`Assets/DuNguyn/Bullets Pack/`, already URP/Lit): SM_Bullet_06 for the revolver, SM_Bullet_09 (a shell) for the shotgun. It measures each round's lathed mesh (`RoundModel`: axis, tip end, radius), saves the casings to `Assets/Prefabs/Weapons/`, and bakes white side-on outline icons to `Assets/Textures/UI/`.
- **Enemies/**: `EnemyController` is a NavMeshAgent state machine (Idle → Chase → WindUp → [Lunge] → Recover, plus Stagger and Dead) with two attacks defined as `EnemyData.Attack` entries: **Strike** (close range, yellow telegraph) and **Lunge** (4–7 m, red-orange telegraph, then a committed dash; needs a clear NavMesh line and has a cooldown). Stagger is threshold-based: each hit carries `DamageInfo.Stagger` (revolver 15, shotgun 6 per pellet, jab/cross 15, hook 30, haymaker 60) and staggers only if it meets the current threshold (the attack's `StaggerThreshold` during a wind-up or lunge, otherwise `BaseStaggerThreshold`). So a revolver shot interrupts a Strike but not a Lunge, while a point-blank shotgun blast (7+ of 8 pellets) does. Sub-threshold hits still deal damage. Stats come from `EnemyData`. `EnemySpawner` runs waves and tracks the living via `Health.Died`.
- **Pickups/**: `Pickup` (health or ammo with a trigger, on the Ignore Raycast layer so the NavMesh bake and firearms skip it). The health pickup is a glowing sphere tinted by `Color`. The ammo pickup is a shotgun shell with two pistol rounds and a gold light, all children of its `Visual` (so they bob, spin and hide together), with `TintVisual` off; the builder rebuilds that model on every run. The builder also owns pickup sounds, setting them on every run: coins for health, the revolver cocking clip for ammo. It's ignored while the player is full. Placed pickups respawn after `RespawnTime`; `EnemySpawner` drops one-shot ones on kills. An ammo pickup gives every firearm its `FirearmData.AmmoPerPickup` (revolver 12, shotgun 4) into its reserve (`StartingReserveAmmo` / `MaxReserveAmmo`), which reloads draw from; `Pickup.Amount` only applies to health.
- **Level/**: `RuntimeNavMeshBaker` bakes the arena's `NavMeshSurface` in `Awake` (execution order -100); there's no saved NavMesh asset.
- **Player/**: `PlayerMovementAudio` (footsteps, plus a land sound after falls), `PlayerHUD` (builds its own uGUI overlay at runtime, so there's no canvas in the scene), `LowHealthBreathing` (looped breathing below 35% health), `PlayerDodge` (dash with i-frames, tuned by `DodgeData`; an enemy calls `TryPerfectDodge` as its strike lands, which on success triggers slow motion, a long `EnemyController.Stagger` and a counter window where weapons multiply damage by `PlayerDodge.DamageMultiplier`), `StyleMeter` (D–SSS ranks tuned by `StyleData` at `Assets/Data/Player/Style.asset`; scores weapon `Hit` events, perfect dodges, kills and multi-kills, finishers and switching weapons between hits; repeating an attack scores less, taking damage and idling drain it; it gates nothing, and `PlayerHUD` draws it on the right edge with callouts), and `PlayerDeath` (disables control, then reloads the scene).

Layers: 8 `Player` (excluded from `FirearmData.HitMask`), 9 `Enemy` (`MeleeData.HitMask`). Arena geometry is on Default, which is what `GroundLayers` and the NavMesh use. Visual feedback (hit flash, telegraph, FX colours) goes through `MaterialPropertyBlock` `_BaseColor` on URP materials. Sound effects live in `Assets/Audio/` and the arena builder assigns them to empty clip slots by file name (`LoadClip`), so renaming a clip means updating the builder. Starter Assets code style is tabs with PascalCase public fields and `_camelCase` private fields; match it.

## Editing Unity assets

When hand-editing `.prefab`/`.unity` YAML or creating scripts outside the Editor, every new asset needs a `.meta` with a unique GUID, and prefab references use `{fileID: 11500000, guid: <script guid>, type: 3}` for scripts and `fileID: 8300000` for AudioClips. Prefer making scene and prefab changes through the Editor or Unity CLI when possible.
