# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity 6 (6000.3.6f1) first-person gothic action game. The design doc is `gameplan.md` (the game is titled "The Crimson Museum" there; the project folder is "Crimson Nights"). Development is in **Phase 1 — Prototype** (combat prototype with cube enemies is built), aiming at the first milestone: *walk into the Grand Gallery, fight a vampire, dodge its attack, shoot it, kill it, keep exploring.* The design doc prefers simple, modular systems (ScriptableObjects for weapons/enemies, NavMesh for enemies) over complex architecture, and keeps scope deliberately small. Check proposed features against its vertical-slice and scope rules.

Git repository (branch `main`, remote `origin` = github.com/ChrisOspina/Crimson-Nights). `.gitignore` excludes Unity's generated folders (`Library/`, `Temp/`, `Logs/`, `UserSettings/`, IDE files). `.gitattributes` routes audio, textures, models, fonts, video and PDFs through **Git LFS**, so new binary types need an LFS rule added there before they're committed. Always commit `.meta` files alongside their assets. No assembly definitions and no tests yet, so all scripts compile into `Assembly-CSharp`.

## Building / running

There's no CLI build pipeline. Work happens in the Unity Editor (installed at `C:/Program Files/Unity/Hub/Editor/6000.3.6f1/Editor/Unity.exe`). The only scene in Build Settings is `Assets/Scenes/SampleScene.unity`, which holds the combat test arena. The arena, player combat setup, data assets and enemy prefab are generated by **Tools ▸ Crimson Nights ▸ Build Prototype Arena** (`Assets/Scripts/Editor/PrototypeArenaBuilder.cs`). Re-running it rebuilds the `PrototypeArena` root and player instance, but reuses existing data assets, materials and the enemy prefab, so delete one of those to regenerate it. When the scene layout changes, update the builder rather than making scene-only edits that a re-run would wipe. Compile errors show up only in the Editor Console (or `Logs/` / `%LOCALAPPDATA%/Unity/Editor/Editor.log`), so changes can't be verified without Unity. Say so when reporting work.

Test Framework 1.6 is installed. If tests get added, run them headless with:
`Unity.exe -batchmode -projectPath . -runTests -testPlatform EditMode -testResults results.xml` (add `-testFilter <name>` for a single test). This needs an asmdef referencing the test assemblies, and the Editor must not already have the project open.

## Key packages

URP 17.3 (separate PC and Mobile render-pipeline assets in `Assets/Settings/`), Input System 1.18 (`activeInputHandler: 1`, new Input System only, no legacy `Input.*`), Cinemachine 3.x (namespace `Unity.Cinemachine`, not the 2.x `Cinemachine` API), AI Navigation 2.x.

## Architecture

A diagram of the player setup, with planned systems, is at `docs/architecture.drawio`. Update it when you add or rewire systems.

The player is built on **Unity Starter Assets – First Person** (`Assets/StarterAssets/`):

- `PlayerCapsule.prefab` (Player tag, layer 8 `Player`) contains `CharacterController`, `FirstPersonController`, `StarterAssetsInputs`, `PlayerInput`, `BasicRigidBodyPush`, plus the project's `PlayerMovementAudio`, `Health`, `PlayerDeath`, `Revolver`, `MeleeWeapon` and `PlayerHUD`. Placeholder cube viewmodels sit under `PlayerCameraRoot`.
- Input flow: `PlayerInput` (Send Messages, using `StarterAssets/InputSystem/StarterAssets.inputactions`) → `StarterAssetsInputs.On<Action>` store plain fields (`move`, `look`, `sprint`, `fire`, `melee`, `reload`, `dodge`) → components read those fields each frame. Button actions only send on press, so `fire`/`reload`/`dodge` are latched flags that the consuming component clears; `melee` (like `sprint`) is a PassThrough action so it also gets the release, which hold-for-heavy needs. The game has **no jumping**: the Jump action, input field and controller jump logic have all been removed, so don't reintroduce them. Current bindings: LMB/RT fire, Space/RB melee, R/West reload, RMB/South dodge. New actions (weapon switching, crouch) should follow the same pattern: add the action to `StarterAssets.inputactions`, add an `On<Action>` handler and field in `StarterAssetsInputs`, then consume the field. Note that `Assets/InputSystem_Actions.inputactions` is the separate project-wide actions asset and isn't what the player uses.
- `FirstPersonController.Update` runs `ApplyGravity → GroundedCheck → Move`, and the camera pitch in `LateUpdate` drives `PlayerCameraRoot` (followed by the scene's `PlayerFollowCamera`, a CM3 `CinemachineCamera` with HardLockToTarget + RotateWithFollowTarget). Don't use the Starter Assets `PlayerFollowCamera.prefab`/`MainCamera.prefab`: they're legacy Cinemachine 2 components. `Grounded` comes from a sphere check against `GroundLayers`, not `CharacterController.isGrounded`. The player only leaves the ground by walking off ledges.
- **The Starter Assets scripts have been modified locally.** Jumping was stripped from `FirstPersonController`, `StarterAssetsInputs` and the mobile `UICanvasControllerInput`; `StarterAssetsInputs` has the combat inputs, and `StarterAssets.inputactions` has Fire/Melee/Reload/Dodge, and `FirstPersonController` has a `MovementLocked` flag (input movement off, gravity and look still on) that `PlayerDodge` sets during a dash. Re-importing the Starter Assets package would overwrite these edits. Prefer adding behaviour in separate components that hook into the controller (events, or reading state in `LateUpdate`) rather than growing the controller itself.

Project-owned code lives in `Assets/Scripts/`:

- **Combat/**: `Health` (shared by the player and enemies; events `Damaged(DamageInfo)`, `Died`; `Invulnerable` ignores damage), the `DamageInfo` struct, and `SlowMotion`, the only code allowed to change `Time.timeScale` (it times itself on unscaled time and survives scene reloads). Anything that deals damage finds the target with `GetComponentInParent<Health>()` on the hit collider.
- **Weapons/**: `Revolver` (hitscan from `Camera.main`) and `MeleeWeapon` (OverlapSphere in front of the camera; tap for light, hold past `HeavyHoldTime` for heavy). Tuning lives in ScriptableObjects `RevolverData` / `MeleeData` under `Assets/Data/`.
- **Enemies/**: `EnemyController` is a NavMeshAgent state machine (Idle → Chase → WindUp (yellow telegraph) → Recover, plus Stagger and Dead). Any hit staggers it, so shooting interrupts a wind-up. Stats come from `EnemyData`. `EnemySpawner` runs waves and tracks the living via `Health.Died`.
- **Pickups/**: `Pickup` (health or ammo, a glowing sphere with a trigger, on the Ignore Raycast layer so the NavMesh bake and the revolver skip it). It's ignored while the player is full. Placed pickups respawn after `RespawnTime`; `EnemySpawner` drops one-shot ones on kills. Ammo goes into the revolver's reserve (`RevolverData.StartingReserveAmmo` / `MaxReserveAmmo`), which reloads draw from.
- **Level/**: `RuntimeNavMeshBaker` bakes the arena's `NavMeshSurface` in `Awake` (execution order -100); there's no saved NavMesh asset.
- **Player/**: `PlayerMovementAudio` (footsteps, plus a land sound after falls), `PlayerHUD` (builds its own uGUI overlay at runtime, so there's no canvas in the scene), `LowHealthBreathing` (looped breathing below 35% health), `PlayerDodge` (dash with i-frames, tuned by `DodgeData`; an enemy calls `TryPerfectDodge` as its strike lands, which on success triggers slow motion, a long `EnemyController.Stagger` and a counter window where weapons multiply damage by `PlayerDodge.DamageMultiplier`), and `PlayerDeath` (disables control, then reloads the scene).

Layers: 8 `Player` (excluded from `RevolverData.HitMask`), 9 `Enemy` (`MeleeData.HitMask`). Arena geometry is on Default, which is what `GroundLayers` and the NavMesh use. Visual feedback (hit flash, telegraph, FX colours) goes through `MaterialPropertyBlock` `_BaseColor` on URP materials. Sound effects live in `Assets/Audio/` and the arena builder assigns them to empty clip slots by file name (`LoadClip`), so renaming a clip means updating the builder. Starter Assets code style is tabs with PascalCase public fields and `_camelCase` private fields; match it.

## Editing Unity assets

When hand-editing `.prefab`/`.unity` YAML or creating scripts outside the Editor, every new asset needs a `.meta` with a unique GUID, and prefab references use `{fileID: 11500000, guid: <script guid>, type: 3}` for scripts and `fileID: 8300000` for AudioClips. Prefer making scene and prefab changes through the Editor or Unity CLI when possible.
